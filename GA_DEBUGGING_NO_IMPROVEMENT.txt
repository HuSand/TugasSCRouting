## THE PROBLEM YOU SPOTTED

From your gen_history, visit_order is IDENTICAL across all generations:

Generation 1: [5539027568, 6935515705, 1721971962, ..., 5539027568]
Generation 2: [5539027568, 6935515705, 1721971962, ..., 5539027568]  ← SAME!
Generation 3: [5539027568, 6935515705, 1721971962, ..., 5539027568]  ← SAME!
...
Generation 20: [5539027568, 6935515705, 1721971962, ..., 5539027568]  ← SAME!

This means:
✗ GA is NOT evolving the permutation
✗ Each generation has the same best_perm
✗ The population isn't diversifying
✗ Crossover and mutation aren't creating different offspring

## ROOT CAUSE ANALYSIS

There are 5 possible reasons:

┌─────────────────────────────────────────────────────────────────────┐
│ CAUSE 1: EARLY STOPPING TRIGGERED IMMEDIATELY                       │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│ Code in GA._route_multi_stop():                                    │
│                                                                     │
│   for gen_idx in range(TSP_GENERATIONS):  # 30 generations max     │
│     fitness = [tour_cost(p) for p in population]                   │
│     best_idx = min(range(len(population)), key=lambda i: fitness[i])│
│     elite = population[best_idx]                                   │
│                                                                     │
│     if fitness[best_idx] < best_cost - 1e-6:  ← CHECK IMPROVEMENT │
│       best_perm = elite[:]                                         │
│       best_cost = fitness[best_idx]                                │
│       no_improve = 0  ← RESET COUNTER                              │
│     else:                                                           │
│       no_improve += 1  ← INCREMENT COUNTER                         │
│                                                                     │
│     if no_improve >= TSP_PATIENCE:  # 20 consecutive gens          │
│       break  ← STOP EARLY!                                         │
│                                                                     │
│ If gen 1-20 show no improvement, it will STOP at gen 20.           │
│ But if initial population is terrible and stays terrible,          │
│ you'd expect it to keep the same best anyway.                      │
│                                                                     │
│ DETECTION: Check logs for "early stop at gen X"                    │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│ CAUSE 2: POPULATION ISN'T CHANGING (MUTATION TOO WEAK)              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│ Current hyperparameters:                                           │
│   CROSSOVER_RATE = 0.85  (85% of new individuals get crossover)   │
│   MUTATION_RATE = 0.6    (60% of children get mutated)            │
│   TOURNAMENT_SIZE = 5                                              │
│   TSP_POPULATION_SIZE = 20                                         │
│                                                                     │
│ What happens each generation:                                      │
│   1. Keep best individual (elitism) ← 1 individual                │
│   2. Create 19 new individuals:                                    │
│      - 85% (16) get crossover                                      │
│      - 15% (3) are just clones of tournament winners               │
│      - 60% (12) of all 19 get mutated                              │
│                                                                     │
│ PROBLEM: If initial population is very similar:                    │
│   • Crossover of similar parents → similar children                │
│   • Mutation (one swap) on 47 stops → tiny change                  │
│   • Tournament selection → always picks similar winners            │
│                                                                     │
│ Result: Population converges to same permutation instantly!        │
│                                                                     │
│ SOLUTION: Increase MUTATION_RATE                                   │
│   Current: 0.6 (60%)                                               │
│   Try:     0.8 (80%) or 0.9 (90%)                                  │
│                                                                     │
│ Or do MORE swaps per mutation (currently: one swap)                │
│   Current code: swap 2 random positions (1 swap)                   │
│   Better: do 2-3 swaps per mutation                                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│ CAUSE 3: TOURNAMENT SIZE TOO LARGE (WEAK SELECTION PRESSURE)        │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│ Current: TOURNAMENT_SIZE = 5                                       │
│   Picks 5 random individuals, returns the best                     │
│                                                                     │
│ With population of 20:                                             │
│   Random pick of 5 means ~25% of population in each tournament     │
│   Usually picks from the top 25% → weak pressure for improvement  │
│                                                                     │
│ COMPARISON:                                                         │
│   Tournament size 2: Very greedy, fast convergence                │
│   Tournament size 5: Moderate (current)                            │
│   Tournament size 10: Weak, allows mediocre individuals            │
│                                                                     │
│ SOLUTION: Reduce TOURNAMENT_SIZE                                   │
│   Current: 5                                                        │
│   Try:     2 or 3  (more greedy selection)                         │
│                                                                     │
│ This forces better solutions to be selected more often.            │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘

## RECOMMENDED FIXES (In Priority Order)

┌────────────────────────────────────────────────────────────────┐
│ FIX 1: Increase MUTATION_RATE (HIGHEST PRIORITY)              │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│ File: src/routing/algorithms.py, line 550                     │
│                                                                │
│ Current:                                                       │
│   MUTATION_RATE = 0.6  # 60% of individuals mutated           │
│                                                                │
│ Change to:                                                     │
│   MUTATION_RATE = 0.9  # 90% of individuals mutated           │
│                                                                │
│ This forces more diversity in the population.                 │
│ Even if crossover produces similar offspring,                 │
│ 90% mutation means most will be different.                    │
│                                                                │
│ ALSO MODIFY: The swap_mutate function (line 725)             │
│                                                                │
│ Current:                                                       │
│   def swap_mutate(perm):                                      │
│     i, j = rng.sample(range(len(p)), 2)                      │
│     p[i], p[j] = p[j], p[i]                                  │
│     return p                                                   │
│                                                                │
│ Better (do multiple swaps):                                   │
│   def swap_mutate(perm):                                      │
│     p = perm[:]                                               │
│     # Do 2-3 random swaps per mutation                        │
│     for _ in range(rng.randint(2, 3)):                        │
│       i, j = rng.sample(range(len(p)), 2)                    │
│       p[i], p[j] = p[j], p[i]                                │
│     return p                                                   │
│                                                                │
│ This creates MORE change per mutation operation.              │
│                                                                │
└────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────┐
│ FIX 2: Reduce TOURNAMENT_SIZE (MEDIUM PRIORITY)               │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│ File: src/routing/algorithms.py, line 542                     │
│                                                                │
│ Current:                                                       │
│   TOURNAMENT_SIZE = 5  # Pick 5 random, return best           │
│                                                                │
│ Change to:                                                     │
│   TOURNAMENT_SIZE = 3  # Pick 3 random, return best           │
│                                                                │
│ This increases selection pressure:                            │
│ • Better solutions are selected more often                    │
│ • Weaker solutions are filtered out faster                    │
│ • Population converges faster but to better optima            │
│                                                                │
│ Effect:                                                        │
│   Smaller tournament = more exploitation (intensify search)   │
│   Larger tournament = more exploration (diversify)            │
│                                                                │
│ With stuck population, you want exploitation.                 │
│                                                                │
└────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────┐
│ FIX 3: Lower TSP_PATIENCE (LOWER PRIORITY)                    │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│ File: src/routing/algorithms.py, line 551                     │
│                                                                │
│ Current:                                                       │
│   TSP_PATIENCE = 20  # Stop if no improvement for 20 gens     │
│                                                                │
│ Change to:                                                     │
│   TSP_PATIENCE = 5  # Stop if no improvement for 5 gens       │
│                                                                │
│ Effect: Stops faster if stuck, frees up compute time.         │
│                                                                │
│ Downside: Might stop too early on a slow-improving problem.   │
│                                                                │
│ Only do this AFTER fixing mutation/tournament.                │
│                                                                │
└────────────────────────────────────────────────────────────────┘
